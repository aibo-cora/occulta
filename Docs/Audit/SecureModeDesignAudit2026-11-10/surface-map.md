## Part A. Entry and session

### A1. Lock/unlock state machine
- `ScreenPhase` = `.covered | .pinRequired | .unlocked`: `Occulta/App/AppScreen.swift:20-27`. `AppScreen` is the scene delegate (injected by `Occulta/App/AppDelegate.swift:19-26`).

- `wire(security:)` `:119` is called from `RootView.task` (`OccultaApp.swift:277-278`), i.e. after first render. `pinDidSucceed()` `:142` simply sets `.unlocked`.

- PIN gate view: `PINEntry` in `.pinRequired` branch, `OccultaApp.swift:388-396`; both `onAuthenticated` and `onDuress` call `pinDidSucceed()` (`:390-391`).
- `PINEntry.swift`: `submitVerify` `:246-256` (0.5 s timing pad `:74`, then `applyVerifyState` + `route`); `route` `:332-354` (`.normal` with `security.state == .duress` -> `onDuress`; `.duress` -> `onDuress`; same success haptic); lockout countdown text `:103-105, 356-363`, `.onAppear` reads `security.lockoutExpiry()` `:151-156`.

- `Manager.Security` fields: `currentDepth` `:49`, `sessionID` `:57`, `state` `:68`, `isRestricted` `:74`, `requiresPIN` `:78`, `isSecureModeActive` `:84`, `coercerBaseDepth` `:114`, `pinEnabled` `:134`. `init` `:160-262`: when `enabled` it calls `deriveSecureModeKey()`, seeds an `AppLayerConfig` row if none exists (`:198-205`), writes `coercerBaseDepth = 0` if nil, fills verifier arrays, fills `pinEnabledPerDepth`, and sets `currentDepth = persistedDepth` only if that depth has PIN disabled (`:~255-260`).
- Duress `PINEntry` for a no-PIN depth: `Settings.swift:278-287` lets a duress-depth user `disablePIN(at:)` for the current depth (persists depth; next cold launch can start at that depth with no gate, `Manager+Security.swift:868`).
